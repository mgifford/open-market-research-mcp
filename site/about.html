MCP

About the local MCP

The browser workspace is static. The deterministic MCP server runs separately on your computer.

This page does not display live MCP data. GitHub Pages cannot start or reach a local stdio MCP server. The browser uses bundled JSON files for rules, sources, the fictional demo, and the public metadata snapshot.

The local server is optional. It adds deterministic tools and two JSON resources for an MCP-capable client; the browser does not need it, and the core workflow has no AI or network dependency.

Run it locally

python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -e .
omr-mcp

Point your MCP client at the absolute path of the virtual environment's omr-mcp executable. The server uses local stdio and makes no live procurement or model requests. On Windows, activate with .venv\Scripts\activate.

Connect a local LLM

LM Studio 0.3.17+ reads Cursor-style mcp.json. Use Program → Install → Edit mcp.json and add:

{
  "mcpServers": {
    "open-market-research": {
      "command": "/absolute/path/to/open-market-research-mcp/.venv/bin/omr-mcp",
      "args": []
    }
  }
}

Jan supports MCP natively: Settings → MCP Servers → + Add MCP Server, transport STDIO, the absolute command, no arguments. Enable it and use a tool-capable model.

Ollama is a model runtime, not an MCP host. Use an MCP host such as mcphost with Ollama, or use LM Studio or Jan. No API key is needed for this server.

The full host-by-host setup, troubleshooting, and the no-MCP prompt-only option are in docs/LOCAL-LLM.md in the repository.

What it exposes

  • Eight read-only tools: source discovery, research planning, accessibility evidence questions, deterministic report drafting, public metadata normalization, OpenACR import, and USAspending record mapping.
  • Two JSON resources: research://sources and research://workflow.

Boundaries: OpenACR import preserves supplier/author claims and does not certify conformance. Public metadata and USAspending mapping preserve provenance; mapping a selected record into a research file requires explicit human approval. See the repository README and docs/ARCHITECTURE.md for the local setup and limitations.

Optional remote MCP: A separate Cloudflare Worker starter is documented in docs/REMOTE-MCP.md. It is disabled by default, public-reference-only, and not deployed. It is not required for this page or the research workflow.

AI

Engaging an AI on this research

Use AI to structure questions, critique evidence, and identify gaps. Keep the evidence and the decision with people.

No AI is run by this page. This is static guidance for an AI conversation you choose to have elsewhere. The page does not send your research to a model, and the local MCP server is optional.

Where AI can help

  • Turn a user need into researchable questions and possible source types.
  • Critique whether a finding is actually supported by the evidence record.
  • Surface contradictions, missing provenance, and unanswered questions.
  • Suggest neutral supplier or agency questions for human review.
  • Draft a report outline without adding facts or citations.

What not to delegate

  • Do not accept invented sources, dates, reviewers, or test results.
  • Do not turn a supplier claim into an independent finding.
  • Do not ask an AI to rank suppliers or choose a winner.
  • Do not ask an AI to declare Section 508 conformance or approve an exception.
  • Do not paste CUI, PII, vendor-proprietary, or procurement-sensitive material into a service without agency authorization and a retention decision.

Prompt patterns

Structure the research questions 
You are helping structure public-sector market research. Do not invent sources or citations.
Acquisition need: [paste the neutral need and user description]
Known constraints: [paste constraints]
Questions I have: [paste your draft questions]
For each question, propose:
1. the uncertainty it tests;
2. a source type that could answer it;
3. a concrete search query;
4. what evidence would answer it;
5. what would remain unverified.
Do not recommend a supplier or conclude Section 508 conformance.
Critique the evidence and find gaps 
Here are my research questions, searches, evidence records, and findings: [paste the JSON or a summary]
Identify:
- claims that are not supported by the cited evidence;
- contradictions between records;
- missing source, retrieval, or as-of dates;
- searches described as completed when they are only reference links;
- findings that should be unresolved questions.
Do not add facts. Ask me for missing evidence instead.
Draft a neutral report structure 
Given these findings and open decisions: [paste the JSON or a summary]
Draft a neutral report outline that separates:
- what was investigated;
- what was found;
- supplier claims;
- missing or contradictory evidence;
- questions for suppliers or specialists;
- decisions that remain with people.
Do not rank suppliers or state that an exception is approved.

If you connect the local MCP

An MCP-capable client can call the local deterministic tools for source discovery, research planning, evidence questions, report drafting, metadata normalization, OpenACR import, and USAspending mapping. The AI still needs human review; the tools do not decide conformance or supplier suitability. See About the local MCP.
